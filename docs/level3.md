# 学習レベル3 ユーザー、担当拠点、変更履歴を管理する

管理者が利用者を作成し、訪問拠点の担当者を割り当てます。担当者の地図と一覧には自分の担当拠点が表示されます。拠点の詳細から、いつ誰が担当者を変更したかを確認できるようにします。

## 学習目標

- 認証で「誰がログインしているか」を確認し、認可で「どの拠点に対して何を実行できるか」を判断する。
- ロールと担当範囲に応じて表示・操作を切り替え、APIから返る `401` と `403` に対応する。
- 担当変更の結果を地図・一覧・詳細に反映し、APIの変更履歴を表示する。

## 準備

1. [レベル2のSPA](level2.md)を用意し、レベル3の配布バックエンドを[共通の起動手順](../README.md#バックエンドの起動)で起動します。ソースから起動する場合は、配布タグ `v3.0.0` のルートで `go run ./src -db places-level3.sqlite` を実行します。
2. 新規DBの管理者のログインIDは `student` です。パスワードは講師の指定値か、初回の起動ログに表示された値を使います。[レベル3のOpenAPI定義](../schema/level3/openapi.yaml)からクライアントを生成します。両方式の起動と生成は[レベル3のSPA実装例](../examples/level3/README.md)を参照してください。
3. 管理者と担当者のセッションを分けるため、別々のブラウザープロファイルから同じSPAを開きます。確認には、担当者に割り当てる拠点Aと、担当範囲外の拠点Bを用意します。

| 操作 | 管理者（`admin`） | 担当者（`assignee`） |
| --- | --- | --- |
| 拠点の検索・詳細・編集・履歴の閲覧 | 全拠点 | 自分の担当拠点 |
| 拠点の登録・削除・担当者の変更 | 可 | 不可 |
| ユーザー一覧・作成・無効化 | 可 | 不可 |

## Step 1 — 管理者が利用者を作成・無効化する

1. `GET /api/session` で取得する `role` を読み、管理者にユーザー管理画面への入口を表示します。`GET /api/users` で利用者の一覧を取得し、`active` から有効・無効を表示します。
2. ログインIDとパスワードを入力し、`POST /api/users` で担当者を作ります。`201` なら一覧を再取得し、`409` ならログインIDが登録済みであることを伝えます。作成した担当者を続く手順でも使う場合は、無効化の確認を最後に行います。
3. 無効化の対象を画面に示し、確定時に `PUT /api/users/{userId}/disabled` を送ります。`204` の後は利用者一覧を更新します。無効化でセッションは失効し、担当割り当ては保持されます。

**完了条件**　管理者が作成した担当者でログインできる。管理者がその担当者を無効化すると、その担当者の既存セッションでも拠点を取得できなくなる。

## Step 2 — 担当者を割り当て、権限に応じて拠点を表示する

1. 管理者が地図または一覧から拠点を選び、詳細の担当者欄から有効な担当者を選べるようにします。`PUT /api/places/{placeId}/assignee` に `assigneeId` を送り、解除の場合は `null` を指定します。保存後は拠点一覧と詳細を再取得します。
2. 担当者としてログインし、拠点一覧APIで取得できた結果を地図と一覧に使います。共有URLで詳細を開くときも、APIで取得できた拠点を表示します。
3. 許可された更新操作を画面に表示します。セッションが有効でも、権限外の更新に対してAPIが `403` を返したら、権限が不足していることを案内します。セッションが無効で `401` の場合はレベル2と同じようにログインへ戻ります。

| 確認する操作 | 期待する結果 |
| --- | --- |
| 管理者が拠点Bを開く | 拠点を表示し、担当割り当てを操作できる |
| 担当者が一覧を開く | 自分の担当である拠点Aが一覧と地図に表示される |
| 担当者が拠点Bの共有URLを開く | 拠点Bの情報は表示されず、拠点一覧を使い続けられる |
| 担当者のセッションで拠点Bを更新する | Swagger UIに担当者としてログインし、有効な本文で `PUT /places/{placeId}` を実行すると `403` が返る |

**完了条件**　管理者と担当者で同じ共有URLを開いて、表示と操作が権限に応じて変わることを確認できる。

## Step 3 — 拠点の詳細に担当変更の履歴を表示する

1. 詳細画面から `GET /api/places/{placeId}/assignment-history` で履歴を取得します。`previousAssigneeLoginId`、`newAssigneeLoginId`、`actorLoginId`、`changedAt` を表示します。担当者が `null` の場合は未割り当てと表示し、履歴が0件の場合も案内します。
2. 担当変更が成功したら、最新の担当情報と履歴を取得します。履歴の実行者と時刻は、APIから取得した値を表示します。
3. 管理者が拠点Aの担当を変更し、履歴が1件増えることを確認します。同じ担当者を再指定した場合と、担当者のセッションで担当変更を試して `403` が返った場合は、管理者の画面で履歴を取り直して件数と最新の内容を確認します。

**完了条件**　変更前後の担当者・実行者・時刻を確認できる。拒否された操作では保存済みのデータと履歴が変わらない。

## 最終確認

- [ ] 管理者が利用者を作成・無効化し、拠点の担当を変更できる。
- [ ] 管理者と担当者の別プロファイルで、同じURLを開いた結果を確認できる。
- [ ] 担当者の権限外の操作がAPIでも拒否される。
- [ ] 担当変更の履歴に成功した変更だけが表示される。
- [ ] 無効化された担当者は、次にAPIを呼び出したときログイン画面に戻る。
