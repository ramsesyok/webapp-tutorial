# 学習レベル4 担当エリアを描き、編集競合を扱う

地図上に担当エリアを1つの多角形として描き、後から頂点を編集できるようにします。同じエリアを複数の画面で編集したときは、先に保存された変更を保護し、後から保存した画面では下書きを保ったまま編集をやり直せるようにします。

## 学習目標

- OpenLayersの `Draw` と `Modify` で多角形を描画・編集する。
- 地図の座標と保存用のGeoJSONを相互に変換し、外周の閉じ方・頂点数・自己交差を確認する。
- `ETag` と `If-Match` を使って編集中の版を伝え、`412 Precondition Failed` に対応する。
- OrvalとHey APIで、型・検証・キャッシュ更新・ヘッダー・エラーの扱いを比較する。

## 準備

1. [レベル3のSPA](level3.md)を用意し、レベル4の配布バックエンドを[共通の起動手順](../README.md#バックエンドの起動)で起動します。ソースから起動する場合は、配布タグ `v4.0.0` のルートで `go run ./src -db places-level4.sqlite` を実行します。
2. [レベル4のOpenAPI定義](../schema/level4/openapi.yaml)からクライアントを生成します。管理者でログインし、「ユーザー管理」で有効な担当者を用意して「担当エリア」を開きます。両方式の起動とコード生成は[レベル4のSPA実装例](../examples/level4/README.md)を参照してください。
3. 競合の確認には、同じバックエンドに接続したブラウザーの2つのタブを使います。両方で同じエリアを編集できることを確認します。

| 操作 | リクエスト | 読み取る内容 |
| --- | --- | --- |
| 一覧 | `GET /api/areas` | 管理者には全件、担当者には自分のエリアの形状が返る |
| 登録 | `POST /api/areas` | 管理者が名前、有効な担当者のID、形状を送る。`201` と初回の `ETag` が返る |
| 詳細 | `GET /api/areas/{areaId}` | `200` の本文にエリア、ヘッダーに `ETag` が返る。担当外の詳細には `403` が返る |
| 更新 | `PUT /api/areas/{areaId}` | 本文にエリアの入力項目、ヘッダーに `If-Match` を送る。担当者は自分のエリアの名前と形状を変更できる |

## Step 1 — 多角形の下書きを地図で編集する

1. 新規作成モードでOpenLayersの `Draw` を `Polygon` として使います。地図をクリックして頂点を置き、最初の頂点をクリックして外周を閉じます。描き終えた多角形を編集用レイヤーの下書きにします。
2. `Modify` を下書きに適用します。実装例では、辺をドラッグして頂点を追加し、頂点をドラッグして移動します。Altキーを押しながら頂点をクリックすると削除できます。編集を終えたらインタラクションを解除します。
3. 既存のエリアを編集するときは、取得した形状を複製して下書きを作ります。キャンセル時は下書きを破棄して、保存済みの形状を表示します。

**完了条件**　新規に多角形を1つ描き、頂点を追加・移動・削除できる。既存のエリアを変形してからキャンセルすると、保存済みの形状に戻る。

## Step 2 — GeoJSONへ変換し、形状を検証する

1. 保存時に表示用の座標から経度・緯度へ変換します。OpenLayersの `GeoJSON` では、`featureProjection` に地図投影、`dataProjection` に `EPSG:4326` を指定できます。取得した形状の再表示では、経度・緯度から地図投影へ変換します。
2. 外周が1本で、末尾が先頭と同じ座標で閉じていることを確認します。閉じるための重複点を除いて3〜200頂点とし、異なる頂点を3点以上含めます。辺の自己交差も検証します。隣り合う辺が共有する端点は、外周をつなぐために必要です。
3. 保存前に不正な形状を見つけたら、理由を表示し、頂点を直せるように下書きを残します。Swagger UIで管理者としてログインし、`POST /areas` のサンプルの `geometry` を自己交差する図形に変えて送ると、`400` と `fieldErrors.geometry` を確認できます。

次は経度・緯度の順で書いた三角形を登録する本文です。`assigneeId` には作成した担当者のIDを指定します。

```json
{
  "name": "ベルリン周辺",
  "assigneeId": 2,
  "geometry": {
    "type": "Polygon",
    "coordinates": [
      [[13.37, 52.51], [13.40, 52.51], [13.38, 52.53], [13.37, 52.51]]
    ]
  }
}
```

**完了条件**　保存して再読み込みしても同じ場所にエリアが表示される。頂点不足や自己交差を画面で検出でき、APIでも不正な形状は保存されない。

## Step 3 — 取得時の版を付けて保存する

1. エリア詳細を取得したときに、応答の `ETag` を読み取ります。`ETag` は、編集を開始した時点の形状と一緒に保持します。
2. 既存エリアを更新するときは、その値を引用符も含めてそのまま `If-Match` ヘッダーに設定します。たとえば詳細の応答が `ETag: "area-7-v1"` なら、編集の保存時は `If-Match: "area-7-v1"` を送ります。
3. 保存に成功したら一覧と詳細を再取得し、確定した形状を表示します。編集を続ける場合は、再取得した形状とその `ETag` を使って下書きを初期化します。

**完了条件**　開発者ツールで、詳細取得で受け取った値が更新の `If-Match` に使われることを確認できる。

## Step 4 — 競合時に下書きを残して最新状態を取得する

1. 古い `If-Match` に対して `412` が返ったら、別の画面で先に更新されたことを表示します。応答本文の `code` は `area_version_mismatch` です。編集中の形状は残します。
2. エリアの詳細を再取得し、最新形状とその `ETag` を取得します。下書きと最新形状を見分けられるようにし、利用者が最新形状を基に編集をやり直せる操作を用意します。
3. 最新形状を基に編集を再開した時点で、保存に使う版をその形状の `ETag` に切り替えます。再取得が終わっただけで、編集中の下書きの版を切り替えないようにします。

| 操作 | 確認する結果 |
| --- | --- |
| タブAとBで同じエリアを開く | 両方の詳細取得で同じ `ETag` を受け取る |
| AとBで異なる頂点編集を行い、Aで先に保存する | Aの形状が保存される |
| Bでそのまま保存する | `412` が返り、Aの形状が保存されたまま、Bの下書きも残る |
| Bで最新形状を取得し、編集をやり直して保存する | 新しい `ETag` を使い、やり直した変更が保存される |

**完了条件**　競合が起きたことを画面で確認できる。Bの下書きを残した状態でAの保存結果を確認し、最新形状を基に保存し直せる。

## OrvalとHey APIの比較

両版で同じ形状と2タブの操作を使い、生成Zod、保存後の再取得、`ETag` と `If-Match`、`412` から競合表示までの経路を確認します。 [Lv4の技術比較](orval-hey-api-comparison.md#lv4-担当エリアの編集競合)

## 最終確認

- [ ] エリアを描画・編集・キャンセルでき、保存後の再読み込みで形状を復元できる。
- [ ] GeoJSONの座標順と閉じた外周を確認し、頂点不足や自己交差を検出できる。
- [ ] 詳細の `ETag` を使って、編集開始時点の版を `If-Match` で送れる。
- [ ] 2つのタブで競合を起こし、下書きを保持してから最新形状を基に保存し直せる。
