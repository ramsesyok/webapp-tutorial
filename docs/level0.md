# 学習レベル0 世界地図で場所を管理する

世界地図をクリックして行きたい場所を登録します。名前・メモ・カテゴリで探し、地図や一覧から詳細を開いて編集・削除できるSPAを作ります。最後に、検索条件と選んだ場所をURLで共有します。

## 学習目標

- OpenAPIからリクエストの送り先、入力の型、成功・失敗時の応答を読み取る。
- Reactのコンポーネント、props、stateを使って、検索フォーム・地図・一覧・詳細を連動させる。
- TypeScriptでAPIのデータを扱い、ピンとカテゴリ別件数を作る。
- 読み込み中、該当なし、通信失敗を画面で区別する。保存後は一覧を再取得する。
- URLを開き直して、選択と検索条件を復元する。

## 準備

1. レベル0の配布実行ファイルを[共通の起動手順](README.md#バックエンドの起動)で起動します。レベル0の基準は配布タグ `v0.1.0` です。リポジトリにある[レベル0のOpenAPI定義](../schema/openapi.yaml)と、[Swagger UI](http://127.0.0.1:8080/swagger/) に表示される内容を確認します。
2. Node.js 22.18以降を用意し、スターターが配布された場合はそれを開きます。実装例を動かす場合は、[Orval版またはHey API版の起動手順](../examples/level0/README.md)に従います。新しく作る場合は、下の手順でReact・TypeScriptをセットアップします。
3. ブラウザーの開発者ツールでネットワーク欄を開き、画面の操作に対応するHTTPリクエストを追えるようにします。

Orval版を読みながら学ぶ場合は、VS CodeでReactの画面構成からAPI呼び出しまで順に追えます。[CodeTourの使い方](../examples/level0/README.md#codetourでorval版を読む)

### 自分でプロジェクトを作る場合

```sh
npm create vite@latest places-map -- --template react-ts
cd places-map
npm install
```

`vite.config.ts` の `defineConfig({ ... })` に次の `server` 設定を加えます。ブラウザーは同じオリジンの相対URLにアクセスし、Viteが `/api` と `/map` をGoバックエンドへ転送します。

```ts
server: {
  host: '127.0.0.1',
  proxy: {
    '/api': 'http://127.0.0.1:8080',
    '/map': 'http://127.0.0.1:8080',
  },
},
```

`npm run dev -- --port 5173 --strictPort` を実行し、ブラウザーでSPAを開きます。

| 確認先 | 用途 |
| --- | --- |
| `http://127.0.0.1:5173/` | Viteで開く開発中のSPA。別ポートで起動した場合はViteの起動ログを参照 |
| `http://127.0.0.1:8080/swagger/` | APIを操作してステータスやJSONを確認 |
| `http://127.0.0.1:8080/api/places` | 一覧APIのJSONを取得 |
| `/map/world.pmtiles` | OpenLayersと `ol-pmtiles` で表示する背景地図。HTTP Rangeリクエストに対応 |

## Step 0 — APIの契約と実行環境を確認する

1. OpenAPI定義の `servers` が `/api` であることを確認します。`paths` の `/places` と組み合わせると、ブラウザーがリクエストを送るパスは `/api/places` になります。
2. `components.schemas` を開きます。`PlaceSummary` は一覧、`Place` はメモを含む詳細、`PlaceInput` は登録・更新の本文です。IDはサーバーが発行し、1件を対象にする操作では `{placeId}` に指定します。
3. Swagger UIで一覧を実行し、`200` とJSON配列を確認します。配列から1件のIDを選び、詳細を取得して `memo` があることを確認します。

| 操作 | リクエスト | 成功時に受け取るもの |
| --- | --- | --- |
| 一覧・検索 | `GET /api/places` | `200` と `PlaceSummary[]` |
| 詳細 | `GET /api/places/{placeId}` | `200` と `Place` |
| 登録 | `POST /api/places` | `201` と作成した `Place` |
| 更新 | `PUT /api/places/{placeId}` | `200` と更新した `Place` |
| 削除 | `DELETE /api/places/{placeId}` | `204` と空の本文 |

**完了条件**　ViteでReactの画面が開き、Swagger UIで一覧の `200` とJSON配列を確認できる。

## Step 1 — 場所の一覧を取得する

1. 一覧APIを呼び出し、取得した配列を `map` で一覧項目のJSXに変換します。Reactの `key` には安定した識別子である `place.id` を使います。
2. OpenAPIに沿ったTypeScriptの型を使います。型やクライアントは生成できます。TypeScriptの型は編集時に値の使い方を確認するもので、ネットワークから届いたJSONを実行時に検証する処理は別途必要です。
3. 通信中、`200` で空配列を受け取った場合、通信失敗を別々に表示します。`fetch` を使う場合は `response.ok` を確認してから本文を扱います。TanStack Queryを使う場合は、クエリの状態と取得データを描画に使います。

**完了条件**　初期データの名前とカテゴリが並び、空配列と取得失敗で異なる案内が出る。

## Step 2 — 一覧のデータを地図に表示する

1. OpenLayersの背景レイヤーで `PMTilesVectorSource` を使い、`/map/world.pmtiles` を読み込みます。講師から背景地図とスタイルが提供されている場合は、その上にピン用のベクターレイヤーを追加します。
2. 一覧の各場所からピンを作り、場所IDを対応づけます。APIは経度・緯度を度で返します。OpenLayersの既定のWebメルカトルで表示するときは、`fromLonLat([longitude, latitude])` で変換します。
3. 検索や再取得で一覧が変わったら、同じ配列からピンも更新します。初期データのブランデンブルク門で、経度と緯度の順序を確認します。

**完了条件**　一覧と地図に同じ場所が出る。ブランデンブルク門はベルリン付近に表示され、一覧が空ならピンも0件になる。

## Step 3 — 地図と一覧の選択を同期し、詳細を表示する

1. 地図と一覧の選択操作から、共通の「場所IDを選ぶ」処理を呼びます。選択したIDを地図と一覧に渡し、両方で同じ場所を強調します。Step 8でURLに移すまで、選択IDはZustandや共通の親コンポーネントで管理できます。
2. 選択したIDで詳細APIを呼び出し、名前・カテゴリ・メモを表示します。TanStack Queryを使う場合は、詳細のクエリキーにIDを含め、IDが決まってから取得します。
3. すばやく別の場所を選んで、直前の場所の遅い応答が表示を上書きしないことを確認します。削除済みなどで `404` が返った場合は、その場所が見つからないことを詳細欄に示します。

**完了条件**　地図と一覧のどちらから選んでも同じ場所が強調され、選んだ場所のメモが表示される。

## Step 4 — APIで検索し、結果から件数を集計する

1. キーワード欄、カテゴリ選択、検索・クリア操作を作ります。入力途中の値はフォームに置き、検索ボタンを押した時点の値を適用中の条件として共有します。
2. `GET /api/places` に `q` と `category` を渡します。キーワードは名前またはメモの部分一致です。カテゴリを「すべて」にした場合は `category` を省略し、両方を指定した場合は両方に一致する場所が返ります。
3. 取得した結果を一覧とピンに使い、カテゴリ別件数も同じ結果から集計します。結果の取得に成功し、選択していた場所が検索条件から外れたと分かったら、選択を解除します。

**完了条件**　キーワードのみ、カテゴリのみ、両方で検索できる。「ベルリン」は名前に含む「ベルリン動物園」と、メモに含む「ブランデンブルク門」に一致する。観光を指定するとブランデンブルク門に絞られる。該当なしでは一覧・ピン・件数が0になり、クリアすると全件に戻る。

## Step 5 — 地図をクリックして場所を登録する

1. 新規登録モードで地図をクリックし、`toLonLat` で得た経度・緯度をフォームに入れます。名前・カテゴリ・メモを入力して `PlaceInput` を組み立てます。空のメモは `memo: ""` として送ります。
2. 名前の空白や座標の範囲など、定義上の制約を確認し、`POST /api/places` にJSONを送信します。`400` や通信失敗の場合はメッセージと入力値を表示します。
3. `201` を受け取ったら、適用中の検索条件で一覧を再取得します。サーバーが確定したID、検索結果への所属、ピンと件数がそろいます。

Swagger UIで登録を試すときは、たとえば次のJSONを使えます。SPAから送る本文も同じ形になります。

```json
{
  "name": "演習用の訪問先",
  "category": "sightseeing",
  "longitude": 139.7671,
  "latitude": 35.6812,
  "memo": ""
}
```

**完了条件**　検索条件をクリアして登録すると一覧と地図に追加され、再読み込み後も残る。検索中は条件に合う場所が結果に表示される。

## Step 6 — 詳細を開いて場所を編集する

1. 詳細の値で編集フォームを初期化し、名前・カテゴリ・経度・緯度・メモを編集できるようにします。
2. `PUT /api/places/{placeId}` に編集項目をすべて送ります。`200` を受け取ったら詳細を更新し、適用中の条件で一覧を再取得します。
3. `400` や `404` のときはエラーを表示して入力を残します。保存に成功して場所が検索条件から外れた場合は、一覧・ピンから消し、選択も解除します。

**完了条件**　名前を変更すると一覧と詳細が、座標を変更するとピンの位置が更新される。カテゴリを変えて検索条件から外すと、詳細も閉じる。

## Step 7 — 場所を削除する

1. 詳細の削除操作で確認を表示し、確定時に `DELETE /api/places/{placeId}` を送ります。
2. `204` は本文が空です。JSONを読む処理を通さず、成功ステータスを確認したら選択を解除し、一覧を再取得します。
3. キャンセル時はそのまま詳細を表示します。削除に失敗した場合は理由を画面で伝えます。

**完了条件**　確認画面でキャンセルすると場所が残る。確定すると一覧・地図から消え、詳細が閉じる。

## Step 8 — 選んだ場所のURLを同僚に渡す

1. 選択IDと適用中の検索条件を `place`、`q`、`category` としてURLに反映します。例は `/?place=1&q=ベルリン&category=sightseeing` です。`URLSearchParams` を使うと、日本語や空白を含む検索語をエンコードできます。
2. 初回表示、再読み込み、ブラウザーの「戻る」「進む」で同じ読み取り処理を使います。実装例はReact Routerの `useSearchParams` を使い、選択と適用中の検索条件をURLから読みます。Zustandは地図の位置指定モードなど、共有URLに含めない画面内の状態に使います。
3. 表示中のURLをコピーできるようにします。別タブで開いて、同じ検索条件がフォームに入り、対応する拠点の詳細を既存のAPIから取得できることを確認します。削除済みの場所を指定したURLでは、詳細欄で理由を案内し、一覧は操作できるようにします。

**完了条件**　サンプル拠点の共有URLから、選択と検索条件が復元される。`127.0.0.1` はURLを開いた人のPCを指すため、同僚との確認は同じ初期データを使い、自分で追加した場所は同じPCの別タブで確認する。

## 最終確認

- [ ] 初期データを表示し、地図と一覧のどちらからも同じ詳細を開ける。
- [ ] 検索・登録・編集・削除の結果が一覧、ピン、件数に反映される。
- [ ] 空の検索結果と、APIの取得・保存失敗を画面で区別できる。
- [ ] コピーしたURLを別タブで開き、再読み込みと「戻る」「進む」でも表示を復元できる。
- [ ] 開発者ツールで、場所APIと背景地図をローカルから取得していることを確認できる。
