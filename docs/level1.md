# 学習レベル1 地図とフォームの両方から拠点を編集する

レベル0の場所を業務で使う「訪問拠点」として扱います。編集用のピンを動かすと経度・緯度欄が変わり、有効な座標を入力するとピンが移動するようにします。保存に失敗した場合は、入力を残してどこを直すか伝えます。

## 学習目標

- サーバーから取得した値と編集中の下書きを分け、キャンセルで元の表示に戻せるようにする。
- 地図のドラッグ操作とフォームの入力を同じ下書きに反映する。
- OpenAPIの制約を読み取り、生成したZodスキーマで入力を検証する。
- サーバーから返った項目別エラーをフォームの該当欄に表示する。

## 準備

1. [レベル0で作成したSPA](level0.md)を用意し、レベル1の配布バックエンドを[共通の起動手順](../README.md#バックエンドの起動)で起動します。ソースから起動する場合は、レベル1の配布タグを使います。
2. [レベル1のOpenAPI定義](../schema/level1/openapi.yaml)を開き、`PlaceInput` と `InvalidPlaceInput` を確認します。`POST /api/places` と `PUT /api/places/{placeId}` の入力不正時に、`400` の本文へ `fieldErrors` が付く場合があります。
3. クライアントとZodスキーマをレベル1の定義から生成します。実装例では `npm run generate:api` を実行します。OrvalとHey APIの設定や起動コマンドは[レベル1のSPA実装例](../examples/level1/README.md)を参照してください。

## Step 1 — 保存済みの値から下書きを作る

1. 編集を開いたときに詳細APIの値からフォームを初期化します。React Hook Formを使う場合は、新規登録を開いたときや編集する拠点を切り替えたときに `reset` で初期値を入れます。
2. 経度・緯度欄は編集中は文字列として扱います。空欄、`-`、`12.` のような入力途中の値をそのまま入力欄に残せます。送信する段階で数値に変換し、空欄が `0` として扱われないよう、変換前に空欄を判定します。
3. 保存済みの詳細は取得データとして保持します。キャンセルしたら下書きを破棄し、地図と詳細に保存済みの値を表示します。

**完了条件**　拠点名や座標を変更してからキャンセルすると、詳細とピンが保存済みの表示に戻る。

## Step 2 — 編集用のピンと座標欄を連動させる

1. 編集中の座標を下書きから読み取り、`fromLonLat([longitude, latitude])` で編集用ピンを表示します。座標が不正な間は直前の有効な位置を表示します。
2. OpenLayersの `Translate` を編集用ピンに適用します。ドラッグが終わったら `toLonLat` で戻し、下書きの経度・緯度欄を更新します。
3. 座標欄に有効な値を入力した場合も、同じ下書きからピンを更新します。React Hook Formの `useWatch` で対象の欄を購読し、ドラッグ後は `setValue` で書き込めます。

**完了条件**　ピンをドラッグすると座標欄が変わり、座標欄に有効な値を入力するとピンが動く。緯度を `100` にすると入力は残り、ピンは直前の有効な位置にとどまる。

## Step 3 — 送信前に入力を検証する

OpenAPIの必須項目と制約を確認し、下書きをリクエスト本文に変換してから生成したZodスキーマの `safeParse` で検証します。React Hook Formではリゾルバーから検証結果を返し、対象の入力欄に理由を表示できます。

| フィールド | 確認する値 |
| --- | --- |
| `name` | 1〜80文字。空白だけの名前は入力エラー |
| `category` | `sightseeing`、`nature`、`food` のいずれか |
| `longitude` | `-180` 以上 `180` 以下の数値 |
| `latitude` | `-85.051129` 以上 `85.051129` 以下の数値 |
| `memo` | 500文字以下。メモが空の場合も `""` を送信 |

OpenAPIの文字数はUnicodeコードポイント数です。JavaScriptの `String.length` はUTF-16コード単位を数えるため、絵文字を含む名前やメモの境界は実装例の補正も確認してください。

**完了条件**　空白だけの名前や緯度 `100` で保存すると、該当欄に理由が出て入力が残る。ネットワーク欄で保存リクエストが発行されていないことを確認できる。

## Step 4 — 保存結果とサーバー側のエラーを表示する

1. 検証に成功したら、登録では `POST`、更新では `PUT` を送信します。成功したら詳細と一覧を再取得するなどして、サーバーが確定した値を表示します。
2. `400` の `fieldErrors` に `latitude` があれば、緯度欄にその理由を出します。フォーム全体には `message` を表示します。React Hook Formの `setError` には対応する項目名を渡せます。
3. `fieldErrors` がないエラーでも、画面に理由を出して下書きを残します。Orval版とHey API版の両方で、クライアントが渡すエラーから項目名と理由を取り出す処理を比較します。

**完了条件**　有効な編集を保存するとピンと詳細が更新される。Swagger UIで緯度に `100` を指定した登録・更新を実行すると、`400` と `fieldErrors.latitude` を確認でき、一覧の件数や更新対象の保存済みの座標は変わらない。

## 最終確認

- [ ] ピンのドラッグと座標欄の入力を両方向で確認した。
- [ ] 保存前にエラーを直せる。別の項目に入力した値も残る。
- [ ] 編集をキャンセルして保存済みの表示に戻せる。
- [ ] Swagger UIでサーバーの入力検証を確認し、画面では項目別エラーを対応する欄に表示できる。
