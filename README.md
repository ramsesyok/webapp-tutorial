# 世界の行きたい場所マップ

世界地図をクリックして、行ってみたい場所をピンとして登録するSPAを作ります。登録した場所は地図と一覧に表示されます。名前やメモ、カテゴリで検索し、見つけた場所の詳細を開いて編集・削除できます。

対象は、JavaやC++などでプログラミングを経験し、ReactとTypeScriptを初めて学ぶ方です。地図・検索フォーム・一覧・詳細・登録編集フォームを1画面にまとめます。

## 学習の目的

- OpenAPI定義からクエリ、パスパラメータ、JSONの型、HTTPステータスを読み取り、ReactからCRUDと検索のAPIを呼び出す。
- TypeScriptで取得したデータを扱い、地図に表示するピンやカテゴリ別の件数に加工する。
- Zustandを使って選択中の場所と適用中の検索条件を共有し、地図・一覧・詳細を連動させる。フォームの入力値は、入力しているコンポーネントで管理する。
- 読み込み中、検索結果が0件、取得・保存に失敗した場合を画面に表示する。

## 教材と実行環境

| 配布教材 | 内容 |
| --- | --- |
| バックエンドの実行ファイル | 講師が受講者のOSに合わせて配布する。場所API、Swagger UI、埋め込みの世界地図をローカルで提供する |
| [schema/openapi.yaml](schema/openapi.yaml) | 場所APIの契約。入力制約、成功・エラー応答、検索の挙動はこの定義を参照する |

### バックエンドの起動

1. 講師から配布された実行ファイルを保存したフォルダでターミナルを開きます。
2. Windows（PowerShell）では `.\webapp-tutorial.exe`、macOS・Linuxでは `./webapp-tutorial` を実行します。
3. [Swagger UI](http://127.0.0.1:8080/swagger/) を開き、APIを確認します。演習中はターミナルを開いたままにしてください。

| URL | 内容 |
| --- | --- |
| `http://127.0.0.1:8080/api/places` | 場所の一覧。CRUDと検索のAPIは `/api` 以下 |
| `http://127.0.0.1:8080/map/world.pmtiles` | バイナリに埋め込んだ地図。HTTP Rangeリクエストに対応 |
| `http://127.0.0.1:8080/swagger/` | Swagger UI。ブラウザからAPIを試せる |
| `http://127.0.0.1:8080/` | `dist` に配置したSPA |

初回起動時に、実行ファイルと同じフォルダにサンプルデータ入りの `places.sqlite` が作成されます。登録・更新・削除の内容はこのファイルに保存されます。

作成したSPAを配信するときは、実行ファイルの隣に `dist` フォルダを置き、その中にビルド成果物の `index.html` と関連ファイルを配置します。[SPAを開く](http://127.0.0.1:8080/)

受講者はReactとTypeScriptの開発環境を使います。Viteで構築する場合は、開発サーバーから `/api` と `/map` をバックエンドにプロキシすれば、画面から相対URLでアクセスできます。地図表示にはMapLibre GL JSとPMTilesを使います。講師がPMTilesの読み込みと背景地図のスタイルを用意すると、受講者はピンの表示と地図上の操作から着手できます。オンプレ環境では、パッケージの入手方法を事前に確認し、実行時に使う地図スタイルやフォントもローカルで配信します。

初期データには、メモに「ベルリン」を含む観光スポット「ブランデンブルク門」と、名前に「ベルリン」を含む自然スポット「ベルリン動物園」があります。「ベルリン」で検索してカテゴリを切り替えると、メモによる検索とカテゴリによる絞り込みを確認できます。

## Step 0 — APIの契約と実行環境を確認する

1. OpenAPI定義で `servers`、`paths`、`components.schemas` を確認する。
2. `PlaceSummary` は一覧用、`Place` はメモを含む詳細用、`PlaceInput` は登録・更新用であることを確認する。場所のIDは登録時にサーバーが発行し、詳細取得・更新・削除ではURLのパスパラメータに指定する。
3. ブラウザの開発者ツールやHTTPクライアントで `GET /api/places` を呼び出し、ステータスとJSONを確認する。Reactの開発サーバーを起動する。

**完了条件**　Reactの画面が開き、一覧APIの `200` とJSON配列を確認できる。

## Step 1 — 場所の一覧を取得する

1. `GET /api/places` から取得した場所の名前とカテゴリを一覧に表示する。リスト項目のReactの `key` には場所のIDを使う。
2. OpenAPI定義に沿ったTypeScriptの型を使う。型は `openapi-typescript` で生成してもよい。
3. 読み込み中、空の一覧、取得エラーをそれぞれ表示する。 `fetch` を使う場合は、JSONを読み込む前にHTTPステータスを確認する。

**完了条件**　サーバーの初期データを一覧に表示できる。空配列と通信失敗を画面で区別できる。

## Step 2 — 一覧データを地図に表示する

1. バックエンドの `/map/world.pmtiles` を背景地図として読み込み、Step 1で取得した一覧から場所ごとのピンを作る。
2. ピンには場所のIDと座標を対応づける。MapLibreへ渡す座標は `[longitude, latitude]` の順にする。

**完了条件**　一覧と地図に同じ場所が表示される。たとえばブランデンブルク門のピンがベルリン付近に表示され、一覧が空ならピンも0件になる。

## Step 3 — 地図と一覧の選択を同期し、詳細を表示する

1. 選択中の場所IDをZustandに持たせる。地図のピンと一覧項目のどちらからも選択でき、両方で同じ場所を強調する。
2. 選択したIDを使って `GET /api/places/{placeId}` を呼び出し、名前・カテゴリ・メモを詳細欄に表示する。
3. 選択を切り替えたら新しい場所の詳細を読み込む。先に選んだ場所の応答が遅れて届いても、現在の選択に対応する詳細を表示する。 `404` では場所が見つからないことを伝える。

**完了条件**　地図と一覧のどちらから選んでも、同じ場所が強調され、一覧では取得していないメモが詳細欄に表示される。

## Step 4 — APIで検索し、画面で件数を集計する

1. キーワード欄、カテゴリ選択、検索ボタン、検索条件をクリアする操作を用意する。入力途中の値はフォーム内に持ち、検索を実行したときに適用中の条件をZustandへ保存する。
2. `GET /api/places` に `q` と `category` をクエリとして渡す。カテゴリが「すべて」の場合は `category` を省略する。キーワードは名前またはメモの部分一致で、カテゴリも指定した場合は両方の条件を満たす場所が返る。
3. 検索結果から一覧・ピン・カテゴリ別件数を作る。件数は現在の結果から計算する。取得に成功した結果に選択中の場所が含まれていなければ、選択と詳細表示を解除する。

**完了条件**　キーワードのみ、カテゴリのみ、両方を指定した検索ができる。該当なしでは一覧とピンが空になり、集計結果は0件になる。条件をクリアすると全件に戻る。

## Step 5 — 地図をクリックして場所を登録する

1. 新規登録フォームで地図上の位置を指定し、名前・カテゴリ・メモを入力できるようにする。メモが空の場合も `memo: ""` を送る。
2. 名前が空白のみの場合や座標が範囲外の場合など、OpenAPI定義の入力制約に沿って案内を表示する。入力値をJSONとして `POST /api/places` に送る。
3. `201` を受け取ったら適用中の条件で一覧を再取得する。登録した場所は、その条件に該当すれば一覧と地図に表示される。APIが `400` を返したらエラーを表示し、入力値を残す。

**完了条件**　検索条件をクリアした状態で場所を登録すると、一覧と地図に追加される。登録後にページを再読み込みしても、APIから登録した場所を取得できる。

## Step 6 — 詳細を開いて場所を編集する

1. 詳細の値を登録フォームと同じ項目に入れ、名前・カテゴリ・座標・メモを編集できるようにする。
2. `PUT /api/places/{placeId}` に編集項目をすべて送る。 `200` を受け取ったら詳細を更新し、適用中の条件で一覧を再取得する。
3. 更新によって場所が検索条件から外れた場合は、一覧・ピン・選択から外す。 `400` または `404` を受け取った場合は、保存に失敗したことが分かるメッセージを表示する。

**完了条件**　名前を変更すると一覧と詳細に、座標を変更するとピンの位置に反映される。カテゴリを変えて検索対象から外したときは、詳細の選択も解除される。

## Step 7 — 場所を削除する

1. 詳細から削除を選べるようにする。確認操作を経て `DELETE /api/places/{placeId}` を送る。
2. `204` はレスポンスボディが空なので、ステータスで成功を判定する。成功したら選択を解除し、適用中の条件で一覧を再取得する。
3. キャンセルした場合はリクエストを送らない。削除できなかった場合は、エラーを画面に表示する。

**完了条件**　削除した場所が一覧と地図から消え、詳細が閉じる。キャンセルした場合は場所が残る。

## 最終確認

- [ ] 地図から場所を登録し、キーワードとカテゴリで探せる。
- [ ] 地図と一覧のどちらから選んでも、選択状態とメモの表示が一致する。
- [ ] 編集・削除が検索結果、ピン、カテゴリ別件数に反映される。
- [ ] 検索結果が0件の場合とAPIリクエストが失敗した場合に、それぞれの状況が画面で分かる。
- [ ] APIのベースURLは `/api` で、画面の実行時に外部の地図サービスへ接続せずに利用できる。
