# レベル3のSPA実装例

[Orval版](orval)と[Hey API版](hey-api)は、[レベル2のSPA](../level2/README.md)にユーザー管理、拠点への担当割り当て、担当変更履歴を加えています。

| 操作 | 管理者 | 担当者 |
| --- | --- | --- |
| 拠点の検索・詳細・編集・担当変更履歴 | 全拠点 | 自分の担当拠点 |
| 拠点の登録・削除・担当者の変更 | 可 | 不可 |
| ユーザー一覧・担当者の作成・無効化 | 可 | 不可 |

## 起動

Node.js 22.18以降とレベル3のバックエンドを使います。ソースから起動する場合は、レベル3の配布タグのルートで次のコマンドを実行します。

```sh
go run ./src -db places-level3.sqlite
```

初期の管理者アカウントのログインIDは `student` です。パスワードは初回の起動ログに表示される値か、講師が `TUTORIAL_INITIAL_PASSWORD` で指定した値を使います。レベル2のDBを引き継ぐ場合は、その複製を `-db` に指定します。従来の `student` とパスワードで再ログインすると、管理者として拠点を利用できます。

別のターミナルで実装例を起動します。

```sh
cd examples/level3/orval
npm ci
npm run dev -- --port 5173 --strictPort
```

Hey API版では `examples/level3/hey-api` で同じコマンドを実行します。ブラウザーで `http://127.0.0.1:5173/` を開きます。もう一方の版を確認するときは、先に起動したViteを停止します。

Viteは `/api` と `/map` を `http://127.0.0.1:8080` に転送します。Viteのポートを変える場合はGoの `-spa-origin` に対応するオリジンを指定します。Goのポートを変える場合はViteの起動前に `TUTORIAL_BACKEND_URL` で転送先を指定します。

## コード生成とデータの再取得

`npm run generate:api` は[レベル3のOpenAPI定義](../../schema/level3/openapi.yaml)からクライアントとZodスキーマを生成します。`npm run dev` と `npm run build` も実行前に生成します。

- [Orval版のAPI呼び出し](orval/src/api/use-management.ts)は、生成フックの `select` でレスポンスの本文を取り出し、更新の入力を `data` で渡します。
- [Hey API版のAPI呼び出し](hey-api/src/api/use-management.ts)は、生成されたオプションをTanStack Queryに渡します。クエリ結果はレスポンスの本文で、更新の入力は `body` で渡します。

担当変更に成功したら、詳細、検索結果、変更履歴を再取得します。ユーザーの作成と無効化に成功したら、ユーザー一覧を再取得します。担当者を無効化するとセッションが失効します。担当割り当ては保持され、管理者が割り当て直すか解除できます。

## ブラウザーでの確認

1. 管理者としてログインし、「ユーザー管理」で担当者を作成します。`/?place=1` を開き、詳細の「担当者」で作成したユーザーを選び、「担当を保存」を押します。
2. 別のブラウザープロファイルで同じURLを開き、作成した担当者でログインします。担当拠点だけが地図と一覧に表示され、詳細の編集と履歴の確認ができます。「ユーザー管理」、新規登録、削除、担当割り当ては管理者の画面で操作できます。
3. 担当者で `/?place=2` を開き、権限エラーを確認します。[Swagger UI](http://127.0.0.1:8080/swagger/) でも担当者としてログインし、拠点2に有効な編集内容で `PUT /places/{placeId}` を実行して `403` を確認します。
4. 管理者の詳細画面で変更前後の担当者、実行者、時刻を確認します。担当を解除すると履歴が1件増えます。同じ担当者を指定した更新や拒否された変更では履歴は増えません。
5. 管理者が「ユーザー管理」で担当者を無効にします。担当者側を再読み込みするとログイン画面に戻り、そのアカウントでは再ログインできなくなります。
